# SkinLabs® — Agentic Web Audit

**Date:** 2026-09-22
**Scope:** Read-only research audit. No redesign, no new "AI-only" files, no fabricated content.
**Objective:** make the public website exceptionally understandable and operable by modern browser agents and AI systems — an LLM-driven browser agent navigating the site, or a crawler with no JS execution — without misrepresenting anything that isn't genuinely there.

**Method:** direct source inspection (file:line citations throughout) across the 30 requested criteria, for the specified routes: Homepage, `/ingredients`, `/ingredients/:slug`, `/ingredients/checker`, `/reviews` (+`/reviews/:slug`), `/briefings` (+`/briefings/:slug`), `/podcast` (+`/podcast/:slug`), `/about`, `/sustainability`, "partner-program", and the public SKYNN AI pages.

**Two route-naming corrections, confirmed directly against `src/App.tsx`, reported up front rather than silently substituted:**
- **`/sustainability` is not a standalone page.** It's `<Navigate to="/about#sustainability" replace />` (`src/App.tsx:114`) — a client-side redirect to a hash-anchor section inside `About.tsx`. Audited as that section, not as its own document.
- **"partner-program" does not exist as a route.** The real public route is `/partners` (`src/pages/Partners.tsx`). Its own JSON-LD calls itself "SkinLabs® Partner Program" (`Partners.tsx:48`), which is likely the source of the naming request. Audited `/partners`.

**Note on a sibling document:** `AGENTIC_WEB_AUDIT_VERIFICATION.md` (present in this repo from a separate, earlier session) is a different, narrower document — a post-merge verification pass confirming the `PERFORMANCE_AGENTIC_AUDIT.md` Top 10 fixes actually landed as described. It doesn't cover the 30-criteria/route-by-route scope requested here; this document is the one that does.

**The 30 criteria** are grouped under each route below rather than repeated 30 times per route; only criteria with a genuine finding (positive or negative) are called out explicitly, everything else was checked and found adequate unless noted.

---

## Executive summary

The codebase's agentic-accessibility foundation is genuinely solid in several places that are easy to get wrong: zero `<div onClick>` anti-patterns anywhere in `src/`, near-universal descriptive alt text, real `cmdk`-based search semantics, and — on the pages that have them — real, visible, clickable source citations (not a black box). Two findings, however, are severe enough to actively undermine that foundation:

1. **`/briefings/:slug`'s SSR route never queried or rendered the article body** (fixed in this pass — see "Implementation status"). The server-rendered response an agent or non-JS crawler actually received at this URL contained only the excerpt and three key-takeaway bullets — the entire article the page's own `Article` JSON-LD claims to describe was absent.
2. **`/reviews/:slug` and `/briefings/:slug`'s SSR routes render with no `<Header>`/`<Footer>`/site navigation at all.** Any agent or visitor landing directly on these URLs (the normal case for a search result or shared link) gets a page with no way to discover the rest of the site. Not fixed in this pass — see reasoning below.

Beyond those two, the remaining findings are narrower and mostly structured-data-accuracy issues: an ingredient detail page whose JSON-LD entity type differed depending on whether it was reached via the SSR route or the client SPA (fixed in this pass); an Organization identity that was declared three different, inconsistent ways across Index/About/Partners (fixed in this pass); a paywall that's correctly disclosed visually but not in structured data (not fixed); and a handful of smaller landmark/link-text/pagination gaps.

## Implementation status (2026-09-22/23)

Following an explicit follow-up request to audit and fix structured data specifically — verifying each schema type's entity genuinely exists, its properties are supported, the information is visible on the page, removing misleading/duplicated schema, consolidating where appropriate, and validating the result — the following were implemented:

- **Organization** consolidated into one shared object (`src/lib/seo-config.ts`'s `buildOrganizationJsonLd()`), reused verbatim on the Homepage, About, and Partners rather than three independently-drifted declarations (finding #20). `logo` now resolves to the theme-appropriate SkinLabs wordmark (`/logosvg.png` light / `/logosvgwhite.png` dark, matching what's now also used live in Header/Footer/Preloader) rather than the previous inconsistent `/pwa-512.png`/`/favicon.svg` mix. `sameAs` now includes the real X/Twitter profile that was missing (finding #1); the duplicate/conflicting WhatsApp channel link was reconciled to one canonical URL.
- **`/ingredients/:slug`'s SPA JSON-LD type mismatch fixed** (finding #8, Critical) — `IngredientDetail.tsx` now calls the same shared `ingredientJsonLd()`/`breadcrumbJsonLd()` builders as its SSR twin instead of a bespoke, differently-typed inline object. Its breadcrumb `<nav>` also picked up the missing `aria-label` (finding #12).
- **`/partners`'s `BreadcrumbList` now matches a real, visible breadcrumb** (finding #21) rather than describing UI that didn't exist.
- **`/briefings/:slug`'s SSR route now renders the real article body** (finding #13, Critical) so its `Article` JSON-LD describes content that's actually present in the response — via the same member/free-tier-aware `get_article_body` RPC the client page uses, called anonymously (correctly withholds premium content, exactly matching what a signed-out visitor sees; not a paywall bypass).
- Production JS source maps were re-enabled (`vite.config.ts`) and the visual header/footer/preloader logos were switched to the new light/dark PNG pair with explicit `width`/`height` — both are separate fixes from a same-day follow-up request, documented in the commit history rather than re-derived here.
- The SSR Header/Footer gap (#14), paywall/sponsorship disclosure work (#15/#16), and the remaining Medium/Low findings above are documented but **not** implemented in this pass — flagged for a follow-up given their larger blast radius (touching every review page's JSON-LD call sites, or the shared SSR shell used by two route families).

See the corresponding code changes for full detail; this document is the audit record, not a changelog.
